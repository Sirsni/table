# ROADMAP — план разработки и путеводитель по скиллам

*Обновлено 2026-07-09. Стратегия: PLAN.md (исходный план), HANDOFF.md (факты). Здесь — актуальный порядок работ и какой скилл когда брать.*

## Текущее состояние
Работает и проверено владельцем: сбор каталога (~9k предметов CS2), цены (автозапрос/лот, USD), история продаж (медианы, продажи/нед/мес), реальная маржа `min(лот, свежая медиана)`, детектор буста, веб-таблица с фильтрами/сортировками, панель сбора, устойчивость к квоте/троттлингу Steam.

## План разработки (по приоритету владельца: точность → скорость → полнота)

### Этап A — «Прибыль математикой» (главное)
1. **Fill rate** — сколько раз/мес реально продают по цене ≤ бида (по price_points) + колонка «ожидаемая прибыль/мес» = fill × реал.прибыль. → скилл `table-profit-detection-campaign`, ФАЗА 1.
2. **Оборот капитала** — turnoverDays, фильтр «не виснет». → там же, ФАЗА 2.
3. **Бэктест** на почасовой истории — проверка стратегии до денег. → там же, ФАЗА 3–4.
   Критерий этапа: топ-20 по ожидаемой прибыли, владелец подтверждает ≥80%.

### Этап B — Кэшаут через площадки
4. **loot.farm** (публичный JSON, MarketProvider, маппинг имён) → `marketplace-integration-campaign` ФАЗА 1.
5. Маршруты Steam↔X в таблице; далее market.csgo (ключ = спросить владельца), Skinport/CSFloat; cs.money последним.

### Этап C — Масштаб и охват
6. Полнота каталога: перебор сортировок/фильтров search/render (цель >25k). → `table-research-frontier` №3.
7. Пул резидентных прокси (только с «да» владельца). → frontier №4.
8. Dota 2 / Rust — просто прогнать сбор (архитектура готова).

### Этап D — Автоматизация (после бэктеста!)
9. Буст-детектор v2 (z-score, тонкий стакан). → frontier №5.
10. Бот: ТОЛЬКО dry-run до явного разрешения; журнал сверяется с бэктестом. → frontier №7, HANDOFF §4.8.
