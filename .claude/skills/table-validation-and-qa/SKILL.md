# Валидация и QA

Не использовать для: процесса коммита/гейтов изменений (→ table-change-control), инструментов измерения (→ table-diagnostics-and-tooling).

## Пирамида доказательств (снизу вверх, все уровни обязательны для логики)
1. `npm run build` + `npm run typecheck` — чисто.
2. Selftest'ы: `npx tsx packages/shared/src/economics.selftest.ts` и `npx tsx packages/collector/src/stats.selftest.ts` → обе печатают `OK (все проверки пройдены)`.
3. Синтетика: fake http + `DB_PATH=/tmp` (шаблон → table-diagnostics-and-tooling); ожидания посчитаны РУКАМИ до запуска, числа обязаны сойтись.
4. Живая проверка владельцем (Steam доступен только ему): попросить полный вывод консоли/скрин; сверить конкретные числа (эталоны: комиссия $1000→$869.58; медиана знакомого предмета против страницы Steam).

## QA-гейт ложноотрицательных (правило №1 владельца)
Любой новый фильтр/метрика перед промоушеном проходит тест: возьми 3–5 известно-прибыльных предметов + предмет с null-метриками — ВСЕ видны в таблице? Текущее поведение (items.ts, задокументировано): null отсеивается ТОЛЬКО если фильтр по этому полю явно задан пользователем; по умолчанию null показывается. Новые фильтры обязаны сохранять это свойство. Молча спрятать прибыльный предмет — худший баг проекта.

## Как добавить selftest
Файл `*.selftest.ts` рядом с модулем; паттерн — простые assert-функции + финальное `console.log("<имя>.selftest: OK (все проверки пройдены)")`; запуск `npx tsx <путь>`; добавь команду в этот скилл и в table-change-control при закреплении.

## Чего нет (честно; кандидаты, не обещания)
CI отсутствует; vitest/фреймворка нет; фикстур сырых ответов Steam нет (сырьё копится только в data/sync-debug.log). Если возьмёшься — через table-change-control.
