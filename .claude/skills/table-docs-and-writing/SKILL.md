# Документация и стиль

Не использовать для: гейтов изменений (→ table-change-control).

## Документы записи
| Документ | Когда обновлять |
|---|---|
| PLAN.md | смена этапов роадмапа |
| HANDOFF.md | КАЖДЫЙ новый подтверждённый факт о Steam/среде (формат: факт + как проверено) |
| .claude/skills/* | при устаревании — правь скилл, не заводи документ рядом |

## Коммиты (образцы: `git log`, напр. 8775cbe, cd239c3)
- Первая строка: что и зачем, по-английски, императив.
- Тело: симптом → причина → фикс → как проверено (числа синтетики: «300/300 collected», «stop at 8/200»).
- Хвост: ссылка сессии как в существующих коммитах. Только ветка `claude/ecstatic-bardeen-elgcwp`, PR не создавать.
- Коммитить цельные срезы (собирается + проверено), не полуфабрикаты.

## Общение с владельцем
Русский; уровень «учащийся программист» (коммит/API знает, сленг ок), но: команды по одной строке (cmd/PowerShell без `&&`), пути Windows. При ошибке просить ПОЛНЫЙ вывод (скрин ок); «мелкие» ошибки не игнорировать. Секреты — никогда в чат (только .env). Стиль ответа: сначала диагноз/итог, потом детали; честно помечать непроверенное.

## Шаблоны
**Фича готова:** что сделано (1–3 пункта) → как проверено (числа) → что сделать тебе: `git pull` → `npm run build` → `npm run dev` → конкретные шаги → что прислать в ответ.
**Запрос диагностики:** какой лог/файл нужен, точная команда его получения, что в нём искать.
