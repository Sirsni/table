# Кампания: детекция реальной прибыли

Не использовать для: теории метрик (→ table-analysis-toolkit), общего роадмапа (→ table-research-frontier).
Цель владельца: точность > скорость > полнота. Успех кампании: топ-20 по ожидаемой прибыли, где владелец подтверждает ≥80% как «реально прибыльно».

## ФАЗА 0 — предпосылки
`GET /api/meta?app=730` → `withStats` существенно > 0; SQL: `SELECT currency, COUNT(*) FROM item_stats GROUP BY currency` — валюты осмысленны (не всё «1» при рублёвом кошельке). Иначе → table-run-and-operate (enrich), при валютном мусоре — перезапустить enrich (перезаписывает).

## ФАЗА 1 — fill rate (сколько раз в месяц реально продают по цене ≤ твоего бида)
Спецификация: `fillVolume30d = Σ qty` точек price_points предмета с `price ≤ buyOrder×1.02`. **Валюты!** points — в валюте кошелька (item_stats.currency), buy_order — в валюте снапшота: обе стороны приводи к USD-центам через toUsdCents, как в items.ts. Где считать: server/src/items.ts, подгрузка точек по id батчем (как statsById). Новые поля DTO: fillVolume30d, expectedProfitUsd = fillVolume30d × realProfitUsd; сортировка по ожидаемой прибыли.
Гейт: у ликвидного commodity (кейс, объём тысячи) fill высокий; у неликвида ~0; 3 предмета сверены вручную SQL-запросом (→ table-diagnostics-and-tooling). Если у ВСЕХ ~0 → проверь валютное выравнивание (классическая ловушка).

## ФАЗА 2 — оборот
`turnoverDays = cSellOrders / (sales30d/30)`; volume в снапшоте = cSellOrders (проверь по runner.ts перед использованием). Фильтр «капитал не виснет» (>14 дней — плохо). Гейт ложноотрицательных: null не прячет предмет.

## ФАЗА 3 — бэктест (наш ров: у конкурентов нет почасовой истории)
Симулятор по price_points: бид на уровне P → «исполнение» точкой с ценой ниже бида → «продажа» по ближайшей последующей медиане → доходность/предмет/месяц. Валидируй на синтетической истории с известным ответом ДО прогона на реальных данных. Гейт: предсказание vs факт на out-of-sample неделе.

## ФАЗА 4 — промоушен в UI
Только через table-change-control + QA-гейт (→ table-validation-and-qa): null-метрики не прячут предметы.

## ОГОРОЖЕННЫЕ ТУПИКИ (не возвращаться)
- Маржа по нижнему лоту = фантом (кейс Cologne 2026: обвал, медиана месяца недостижима — потому realSell = min(лот, свежая медиана)).
- Фильтры по непроверенным порогам — нарушение доктрины.
- Доверие total_count из пустых страниц; медианы без min-клампа.
